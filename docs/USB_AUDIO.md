# 接收器 USB 音频与模式切换

USB 音频是电脑上的录音输入设备。采样率、位深、声道数只通告当前
“音频输入设置”的一个组合；PCM 小端数据直接输出，不重采样、不改变
位深、不把单声道复制为立体声。主机可以控制静音。

修改输入格式时，清空旧 RF 音频帧，断开 USB 后用新描述符重新枚举。
序列号由芯片 MAC 和格式组合生成，避免 Windows 沿用旧格式描述符。
录音软件需要重新打开发生格式变化的输入设备。只改增益不会重新枚举。

音频模式下选择不支持的输入格式，或用不支持的输入格式开启音频模式，
会显示“USB带宽不足 / 请降低音频格式”，并恢复之前的设置和控件焦点。
其他 USB 模式不限制无线音频输入。历史配置若保存了不支持的 USB 音频
组合，启动时保留输入格式、关闭 USB，并在串口记录原因。

## 支持的输入组合

| 采样率 | 单声道 | 立体声 |
|---|---|---|
| 48 kHz | 16 / 24 / 32 bit | 16 / 24 / 32 bit |
| 96 kHz | 16 / 24 / 32 bit | 16 / 24 bit |
| 192 kHz | 16 / 24 bit | 不支持 |

限制同时考虑全速 USB 和 ESP32-S3 的硬件 FIFO。当前 TinyUSB DWC2
驱动为接收 FIFO 分配 62 个 32 bit 字，EP0 IN 占 16 字、CDC 通知占
2 字、CDC IN 占 16 字；256 字的硬件 FIFO 剩余 160 字，即音频端点
最多 640 字节。每毫秒最大包还预留一个完整采样时隙供异步时钟校正。
因此 192 kHz / 16 bit / 立体声和 96 kHz / 32 bit / 立体声也无法在
当前音频加 CDC 配置中使用，不能只按理论 12 Mbps 带宽判断。

## 四种模式的生命周期

关闭、音频加 CDC、TF 读卡器、USB Serial/JTAG 共用一个 USB 所有者任务。
UI 和 CDC 下载请求只提交目标模式；所有 TinyUSB 事件处理、PCM 写入、
初始化和释放均由该任务执行，不再异步删除运行中的协议栈任务。

切换时先移除设备连接，完成协议栈和 PHY 的释放，再恢复 TF 本机文件
系统；至少留出 250 ms 的断开间隔后启用目标设备。快速修改会合并为
最新目标。关闭模式显式禁用 Serial/JTAG 引脚，避免只释放 PHY 后旧
硬件设备仍留在 USB 总线上。初始化失败会清理已申请资源并重试。

音频停止、设备拔出或总线复位会清除流状态；挂起期间停止供给，恢复
后保留主机原来选择的流接口。无完整 RF 音频帧时提供静音，缓冲区满时
不覆盖旧数据或写入半个采样。重新打开录音流只重置 USB 读取位置，不
影响 3.5 mm 输出。

## 可重复的验证

从 Receiver 目录运行（替换编译器和输出目录为本机路径）：

```powershell
& C:/Users/dudu233/.platformio/penv/Scripts/pio.exe run -e debug
& C:/Users/dudu233/.platformio/penv/Scripts/pio.exe run -e release
& C:/Users/dudu233/.platformio/penv/Scripts/python.exe test/usb_audio/run.py `
  --compiler-bin 'C:/Program Files/JetBrains/CLion 2023.1.3/bin/mingw/bin' `
  --output "$env:TEMP/receiver-usb-audio-qa"
& C:/Users/dudu233/.platformio/penv/Scripts/python.exe test/usb_audio/ui_run.py `
  --compiler-bin 'C:/Program Files/JetBrains/CLion 2023.1.3/bin/mingw/bin' `
  --output "$env:TEMP/receiver-usb-ui-qa"
```

USB 主机检查编译生产 USB 描述符、音频模块、模式控制和 RF 音频缓冲，
使用实际 TinyUSB device/audio/CDC/MSC 栈；仅物理控制器、调度、TF 介质
使用替身，串口 Stream 使用生产实现和桌面 Arduino 基类。覆盖 18 种
格式、描述符及 AC 长度、固定时钟的分段请求、PCM 字节一致性、缺失
分片补静音、静音控制、缓冲背压、流关闭/重开、复位/挂起、全部模式
对的 400 次切换、CDC 关闭及切换时写入、格式序列号、快速请求合并
及初始化失败恢复。
UI 检查使用实际 LVGL 和 UI/字体/图片，驱动真实下拉框事件，检查提示
文字、设置回退和焦点恢复，检查说明文字及焦点轮廓的完整边界，输出
160x80 截图。USB 页面固定为 24 px 模式行、2 px 间隔、30 px 两行
说明；同时修复返回上级时误把行的动画标记当成页面指针造成的崩溃。

2026-09-18 验证记录：PlatformIO debug、release 均通过；18 种格式
检查中 13 种可用、5 种拒绝，400 次模式切换及失败恢复通过；实际
LVGL 控件检查和 22 张截图检查通过；三套字体的全部字符验证通过。

## 尚需实机验证

本次环境未连接接收器，以下项目尚未验证，桌面替身不能替代这些证据：

- Windows 实际枚举和录音；13 种格式均出现在录音设备的格式选择中，
  包括 48 kHz / 16 bit / 立体声、192 kHz / 24 bit / 单声道。
- 用发射器输入测试信号，检查左右声道、幅度、持续录音、RF 抖动和
  USB/I2S 时钟漂移；最大格式持续录音时不应出现断续、爆音或看门狗复位。
- 修改输入格式后录音软件重新打开设备，新格式正确，旧活动音频端点
  和串口消失；BLE 收敛至 48 kHz / 16 bit / 单声道时 USB 同步更新。
- 四种模式的全部切换顺序、快速切换、带线启动、拔插、电脑挂起/恢复；
  检查实际连接设备、盘符、串口，区别于设备管理器保存的离线历史项。
- 读卡器切换后 TF 文件系统重新挂载，电脑和本机不会同时访问介质。
- 160x80 实屏提示框、最长格式文字、焦点和双键确认。
- debug 串口每 10 秒输出 `USB task minimum free stack`，检查录音及
  读卡器大量传输后的剩余栈空间，以及堆内存是否随切换次数持续下降。
